# 自迭代机制

> 本运行时最特别的性质：SKILL.md 会修改自己，且修改过程有与起草者隔离的攻击评审、有备份、有回滚、有验证判据。完整协议见 [`SKILL.md`](../SKILL.md) 第八节 D 条款；本文说明设计动机与两轮真实迭代的记录。

## 为什么需要自迭代

无人值守运行时最大的长期风险不是单轮失败，而是**自身退化**：参数过时、条款与现实漂移、教训反复发生却没人沉淀。传统 skill 的迭代靠作者手动维护；本运行时把迭代本身也交给运行时——用同一套"证据锚→缺陷→修订→评审→备份→应用→验证"的回路维护自己。

## 协议要点（八-D 条款的骨架）

1. **触发两型**：用户发起轮（修订即时应用）；自主轮（收工拍计数教训候选≥3 条触发，单夜至多一轮，持锁运行）。
2. **规程七步**：通读运行证据 → 缺陷清单（每条带证据锚，无证据进待观测）→ 归因起草 → **隔离子代理攻击评审** → 备份 → 逐条 diff 应用（自主轮先进 pending 冷却区，用户未否决次日才生效）→ 验证判据落盘，修订后第一个运行夜为验证夜。
3. **边界**：只改本手册与项目目录文件；执行内核与全局协议绝对只读；全程禁分。
4. **降级链**：评审子代理不可用→全部降级待观测；累计两轮评审未过→降级；pending 有害→用户否决即回滚。

## 两轮真实迭代记录

### v1.1 → v1.2（首夜自迭代，产出八节四条款）

| 缺陷（立项依据） | 产出条款 |
|---|---|
| 状态文件"重写"退化为追加（历史与快照混杂） | 条款 A：重写语义（全文替换+节名清单+自检） |
| 运行锁写纪律不可判定（崩溃残留如何处置无规则） | 条款 B：锁三态纪律（done/在跑/污染+归属校验+心跳） |
| 教训上升通道缺失（"同一坑两次"无人登记） | 条款 C：教训上升检查（三条判据+固定路径） |
| 自迭代本身无协议 | 条款 D：自迭代协议（本文） |

评审三轮：首轮全不过——隔离评审代理抓出三个结构伤：**done 毒化**（收尾标记被当作可复用状态）、**清单自斥**（条款例子违反自己的规则）、**自主轮持锁**（自迭代轮与普通拍抢锁）。全部修复后三轮全过，备份+逐条 diff 应用。"自主轮默认生效"的授权经用户事后追认。

### v1.2 → v1.3（通用化改造）

用户定调"运行时本质=长周期产品飞轮，夜间只是初始背景"后立项 4 个缺陷：夜间限定表述与全天候实践矛盾/参数名双轨/无跨项目调用流水/台账缺位。

两路隔离攻击评审初评不通过，9 项必须修，代表性问题：

- **旧触发词被删**——"今晚主题"等历史表述保留为同义注记，否则既有 cron 立即失配（向后兼容意识）；
- **台账写入时点未锚定**——"收尾时写一行"不够，必须锚定在归属校验之后、锁写 done 之前的精确位置，否则被接管的实例会写脏行；
- **路径豁免遗漏**——台账是全局元记录，须显式豁免"产出只写产出目录"纪律，否则条款自相矛盾。

第三路复审通过后应用。v1.3 = 去夜间限定 + 九节调用台账。

## 设计启示

- **攻击评审必须真隔离**：起草者自查会系统性放过自己的假设；隔离子代理以"找出必改项"为目标，一轮抓 9 项是正常产出；
- **修订要可回滚**：备份目录+diff 编号+验证夜核对失败自动反向删除，"可以安全地试错"是自主迭代的前提；
- **自主修改要冷却**：pending 机制把"机器自己改自己"的每一次变更都置于用户的否决窗口内——自主性与可控性不冲突。
