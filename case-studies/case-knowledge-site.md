# 案例 1：知识网站——产品迭代完全体

> 一个由纯视觉组件构成的知识内容网站，从零起步昼夜连转约 26 轮（r1-r26），每轮约 1 小时。这是持续学习飞轮方法论和多实例并行协议的诞生地，也是 SKILL.md 中校准条款最多的来源。

## 怎么跑的

- **节拍**：cron 定时触发，每轮一个独立可回退的 commit；跨夜连续性完全靠落盘文件（PROJECT.md 收口+进展日志），不靠会话记忆。
- **验收分工**：AI 夜间连续迭代，用户白天异步抽查给方向。用户原话定调："我只是提供验证视角"——用户不在场不是停机理由，用户反馈是最高权重输入。
- **前提重构**：用户一次性授权"绿灯思维+纵向溯源"（表前提→深前提→再深一层），把"每个候选必须等用户裁决才能推进"重构为"合规自检通过即推进+用户异步抽查"，重构过程落盘（溯源链+回退方法）。

## 沉淀一：持续学习飞轮（写进了 SKILL.md 校准节）

每轮固定执行五步：**验证暴露差距 → 差距转译成学习问题 → 针对性搜索学习 → 结合真实需要转化 → 再验证**，配量化对比和知识库持久化。

两条用户纠偏成为所有后续项目的认知纪律：

1. 学习是每轮的固定步骤，不是一次性储备；
2. **学原理不学表象**——验证标准是"是否表达论点+生命感"，不是"像不像参照物"。

配套发现：**参数缩水陷阱**（同一坑踩两次）——学到的语言在执行时会被旧的克制惯性打 2-3 折。对策是参照帧与自己产出**并排比对+量化指标**（如亮度直方图统计），禁止自评"差不多"。

## 沉淀二：多实例并行协议（r6 四拍多 agent 试点）

同机两个 AI 实例并行同一任务时，会互认对方为"幽灵"：控制台出现非本会话的探针、URL 被改写成别家的查询串、浏览器前台互抢、自家刚产出的文件被对方判"来源不明遗留"移出版本库。

对策四要素（全部进了 SKILL.md"多实例并行协议"条）：开工先 `git log` + 产出目录查重认亲；文件名带实例标识；浏览器按 pid 隔离操作；共享文件写前查修改时间、单次原子写。

四拍结构：验证者 → 学习者 → 执行者 → 协调者，交接卡带六字段（占用清单/环境状态/上游 commit 指纹/二值判定词表/实例标识/互斥资源登记）。

## 沉淀三：浏览器验证纪律

- 沙盒仅作初筛，授权后真实浏览器优先（真实环境的 rAF/输入/合成帧全部正常）；
- 粘贴导航会被地址栏下拉劫持——可靠路径是点击地址栏+全选+键入完整新 URL+回车；
- 动画/场景页验收一律 URL 参数直渲帧（确定性抓帧），不做"滚动+等补间+截图"路径。

## 结果与退出

26 轮后全项视觉验收通过，转入 backlog 待触发态——用"暂停令+恢复卡"干净退出：恢复卡记录到哪一步、下一步是什么、怎么验证。这是"事件触发待命"形态的首个实例。
