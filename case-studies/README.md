# 案例研究

> 以下案例来自同一台机器上约两个月的真实运行（2026-08 至 2026-10）。项目名称做类型化处理，时间取月级，数字取量级；机制细节全部可对应回 [`SKILL.md`](../SKILL.md) 的条款与校准节。

## 五个实例一览

| 案例 | 形态 | 节拍 | 量级结果 |
|---|---|---|---|
| [案例 1：知识网站](case-knowledge-site.md) | 产品迭代完全体 | 约 1 小时/轮，昼夜连转 26 轮 | 持续学习飞轮方法论诞生地；多实例并行协议实证 |
| [案例 2：长篇小说流水线](case-novel-pipeline.md) | 内容量产 | 15 分钟/班，全天连跑 | 单日数十章、约十万字量级；"熔炉"规范进化层 |
| [案例 3：桌面宠物产品](case-desktop-pet.md) | 软件产品飞轮 | 30 分钟/轮 × 9 轮（单日内） | 三角色轮转+先考古后动手的完整标本 |
| [案例 4：放置游戏](case-idle-game.md) | 端到端交付 | 30 分钟/拍连跑十余拍（单夜） | 概念→实现→实测调平→评审验收全链完成 |
| [案例 5：运行时本体](case-runtime-itself.md) | 研究/核验/自迭代混合 | 30 分钟节拍多段接力 | 单夜六个独立任务实例并行；skill 自迭代两轮 |

## 形态光谱（实践中演化出的维度）

**时间形态**：夜间通宵 → 昼夜连转 → 白天单拍 → 事件触发待命（backlog 态）→ 单会话快速飞轮。

**节拍形态**：15 分钟（内容流水线）/ 20-30 分钟（开发迭代）/ 1 小时（产品打磨后期）/ 秒级守护拍（运营型飞轮的静默态：连续静默拍=设计稳态而非故障）。

**任务类型**：研究核验、内容量产、软件产品迭代、运营守护、元迭代（skill 修改自己、规范层进化）。

**协作结构**：单代理 → 三角色 → 四拍多代理（验证者→学习者→执行者→协调者）→ 六卡议会（人格化审计）。

**用户介入模式**：夜间跑白天验收 → 异步抽查（"我只是提供验证视角"）→ 批注插队最高优先 → 渐进放权 → 暂停令+恢复卡。

## 跨案例稳定沉淀的机制内核

状态在磁盘不在上下文 / 运行锁+心跳 / 虚白清单=验收入口 / 每轮独立可回退 / 禁分禁编造 / 熔断·挂起·守护三态 / 空触发打卡 / 暂停闸+恢复卡。

架构模式：**共享机制内核 + 各项目自建本地协议层**（每个项目有自己的本地协议文件：节拍、角色分工、授权范围）。
