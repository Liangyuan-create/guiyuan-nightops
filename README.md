# 归元夜航（guiyuan-nightops）

> 一个让 AI coding agent 在**无人值守**下跑长程任务的运行时 skill：你说清目标和验收标准，它按节拍自主推进、产出全部落盘、卡住就挂起留给你裁决——白天花十分钟验收。

名字里的"夜航"是历史命名（初版为夜间定时任务设计）；现在它是通用型运行时：夜间通宵、昼夜连转、白天单拍、全天内容流水线都是它的已实证形态。适合 ZCode / Claude Code 等支持项目级 `AGENTS.md` 自动加载与定时任务的 agent 工具。

---

## 它解决什么问题？

把一个大致目标交给 AI 让它自主跑一整晚，你会遇到两种经典失败（本项目的理论层称之为无人值守的两大病理）：

- **空转**：无限自我纠偏，烧掉大量 token 却不产出——反复"再检查一遍""再优化一下"；
- **妥协**：悄悄降级目标，交出一个看起来完成了、实际糊弄的东西。

归元夜航用**结构性纪律**而不是"更聪明的模型"来对抗这两者：

| 病理 | 对抗机制 |
|---|---|
| 空转 | 空转熔断五步仪式、轮数封顶、时间预算无条件停机、"实质维度计数"收敛判据（连续两轮无新增实质维度才算收敛，不许"感觉好了"） |
| 妥协 | 验证点只有"通过/未通过+外部证据"两种状态；**交付物全文禁分**（不出现任何自评分/百分比/进度数）；卡住必须挂起并写明缺口，禁止带着缺口硬收敛 |
| 失忆（第三种：跨夜失忆） | **状态在磁盘不在上下文**——每轮收尾四步落盘，每轮开跑强制读盘恢复；上下文被压缩也无所谓 |
| 无人看管时的方向漂移 | 虚白清单=轮后验收入口；你的批注是最高权重输入，插队生效 |

## 核心机制一览

- **参数缺失即拒跑**：没有"本轮主题+真问题、产出目录"就不启动，不猜测、不代填；
- **运行锁三态**：在跑 / done / 污染——多实例并行不互踩，崩溃残留 25 分钟后自动接管；
- **熔断·挂起·守护三态**：连续 3 轮无实质进展触发五步复位；关键变量缺失挂起跳过（进虚白清单）；运营型任务连续静默拍=设计稳态；
- **时长锚定红线**：一切时长/数量记录以 `date` 命令或文件时间戳为锚，估算=编造数据（本项目真实事故沉淀：17 分钟曾被写成 90 分钟）；
- **自迭代协议**：skill 修改自己，但修订必须先过**隔离子代理攻击评审**，有备份、有回滚、有验证夜——见 [`self-iteration/`](self-iteration/)；
- **调用台账**：跨项目一行一流水，仅追加，为复盘提供使用侧证据。

运行时全流程见架构图：[`architecture/runtime-logic.md`](architecture/runtime-logic.md)。

## 快速开始

1. **安装**：把本仓库的 `SKILL.md` 与 `kernel/workflow-b-v1.3.md` 放进你的 agent skill 目录（保持两者相对路径，或把 SKILL.md 中的内核路径改成你的实际位置）。
2. **建项目**：新项目根目录放一份按 [`templates/AGENTS-template.md`](templates/AGENTS-template.md) 改的 `AGENTS.md`（路由锚+红线），再建产出目录（五件套结构见 [`templates/output-directory-template.md`](templates/output-directory-template.md)），调度时写入目标卡。
3. **接调度**：配一个 cron 定时任务（prompt 自包含：装载清单+主题+硬约束），或手动说"开始夜航"。首夜建议选交付导向强、验证成本低的主题。
4. **验收**：白天打开产出目录的 `虚白清单.md`——验证点逐项过/未过+证据、需要你裁决的问题、建议的下一个验证点，十分钟够用。

执行内核（工作流 B 稳定版）是一份独立完整的认知工作流：澄清闸门 → 120/60 目标架构 → 四阶认知循环+六控制器 → 输出层防火墙 → 现实验证外环。夜航层只是把它改造成无人值守形态（详见 `SKILL.md` 第二节的修正表）。

## 边界与如实申报

- 本运行时假设你能接受"AI 整夜/全天自主运行"的 token 消耗模式；时间预算（默认单轮 150 分钟）只是防呆上限，实际节奏由实测校准；
- 自主轮的边界写死：不花钱、不对外发送、不订外部服务、只写产出目录；执行内核与全局协议绝对只读；
- 运行时不自评任何分值——如果你需要"AI 给自己的表现打分"，这个项目在设计上就拒绝（见内核零节反结构幻觉原则）。
