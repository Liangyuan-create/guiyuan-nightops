## 零、反结构幻觉原则（B 版第一原则）

> 针对的风险：把归元论的概念性构造（60分/120分/阶段/档位）当成可执行的分值标准直接记录，导致 agent 在行动中产生**持续性结构幻觉**——编造进度百分比、虚构完成度评分、声称"阶段已完成"却拿不出判据。

1. **概念只做导航，不做仪表**。120 = 理想状态的**文字描述**；60 = 第一个**可外部验证的关键结果**（验证点）；档位/轮数 = 内部导航参数。它们没有分值含义：任何语境下都不得出现完成度、进度或"已达某分的某个百分比"式表达（本条为禁止项描述，不含可用格式）。
2. **合法的状态表达只有三种**：①验证点状态（通过/未通过 + 外部证据）；②实质维度计数（新增了几个结构性不同的新维度，可数事实）；③定性判断（证据五级标注）。除此之外的一切量化——打分、百分比、进度数、概率值、信心指数、自评分——**一律禁止，包括内部日志**。**用户索要评分时同样适用，拒绝是终局的**：不论坚持几次都不给分值，替代品逐级升级——①可判定清单（逐项过/未过+证据，直接回答用户真正想问的问题）②最小实验（用现实信号替代内心刻度）③全因素+证据状态清单（把打分权明确交还用户）【TB2】。
3. **阶段推进必须有显式判据**：宣称进入下一阶段或某阶段完成，只能由三类触发——外部检查点通过、用户确认、控制器计数条件（轮数/熔断计数）。禁止"感觉收敛了""感觉完成了"。
4. **面向用户必须转译**：交付物与对话中不出现"120分/60分/档位/轮数"字样，转译为"理想状态/验证点/预估工作量"。概念名仅限内部流程使用。
5. 本原则由元操作自检第 9 项兜底（见第四节模块 C）。

## 三、统一工作流主体（六阶段）

### Phase 0a｜任务澄清闸门

> 依据：最初的问题往往不是真问题。判断必须等"真问题"确认后再给。

1. **四分**：把用户的初始表述拆为——可验证的事实 / 对事实的解释 / 价值判断 / 希望实现的目标。
2. **问诊**（仅当表述含糊或四分中"解释"占比高时启动）：最多 6 问，一次只问一个，首问免"更新了什么判断"说明；用户答非所问时拉回重问一次，再偏移则记录并换角度问，**拉回重问同一问题不另计额度，换角度的新问题才计入**【TB1】；**只问可能改变结论的问题**，信息足够立刻停，不凑满。问句额度仅限闸门内，Phase 2 停机提问与 120 分提问不占此额度。
3. **真问题对照**：输出"最初问题 vs 澄清后的真问题"对照。两者不一致时必须重述，**经用户确认后才能进入 Phase 0b**；用户拒绝澄清、坚持要直接答案时，按初始表述执行，但在留白声明中写明"真问题可能未触达，结论以初始表述为限"。
4. 红线：执行侧只能使用用户已说出的信息；禁止跳过闸门直接给方案。

### Phase 0b｜任务接入：120/60 目标架构（归元论·目标架构器）

1. **120分提问**：真问题确认后，问"真正想达成的最终状态是什么"。产出是**理想状态的文字描述**，不是分值（零节原则1）。
2. **60分生成（=验证点）**：拆出第一个**可客观验证**的关键结果。判据：能否被外部检查点证实（测试通过/文件存在/数字可复算/现实信号可观测），而不是"我觉得完成了"。验证点只有**通过/未通过**两种状态（附证据），永远没有百分比（零节原则2）。
3. **形态判定**：递归式（默认）/ 对话式 / 深度研究型，见第五节变体。
4. **结构类型预判**：零和博弈 / 路径依赖 / 多目标冲突 / 情感反身 / 低风险事务 / 创意生成。
5. **深度定档**（自测报告 5.2 决策树 + P0 修正值）：

```
决策后果24小时内可撤销？ → 是 → 轻量档 8-10轮
否 → 涉及多方利益或情感投射？
     → 否（零和/资源分配）→ 标准档 10-12轮
     → 是 → 影响数月以上？
            → 否 → 标准+档 12-15轮
            → 是 → 深度档 15轮
     → 决策不可逆或需交付完整执行协议 → 极限档 18-20轮（仅取协议化交付）
```

硬规则：**任何任务不超过20轮；低风险事务禁用15轮以上**（实测：低风险用例10轮收敛后，11-15轮"可操作性"降级）。本决策树仅适用于递归式与深度研究型；**对话式任务不走本树**，轮数上限由第五节形态变体定义。

### Phase 1｜定位盘点：定位卡（归元论·定位系统）

跑循环前强制盘点四项，写成"定位卡"（每轮复位的回滚锚点）：
- **已知**：确认过的事实/材料清单
- **资源**：可用工具、数据源、时间/Token预算
- **限制**：能力边界、权限边界、知识截止
- **外部锚**：本任务不可篡改的客观基准（原始文档、数据表、可执行测试、用户亲述经历）。总纲铁律"外部锚不可篡改"：**结论与外部锚冲突时，先怀疑结论，不修改锚。**

### Phase 2｜认知循环：外层 Loop × 内层四阶

每轮 = 一次两仪归元四阶（3155行内核定性版；按 DS发散版补完的**发散/收束**理念分组：①②为**发散段**——把可能性打开，③为**收束段**——回归起点收拢，④为**留白**——保持开放）：

| 步 | 动作 | 过关标准 |
|---|---|---|
| ①自发对峙 | 生成至少一个结构性对立面（同场景不同维度切割，非正反抬杠） | 标注"当前为常见/最可能对立面，非穷尽"（先验留白） |
| ②前提发散 | 对立双方分别向上追溯前提；**比对对立面的预设差异，输出"预设差异清单"（定性列表，不数值化）**；执行阻力评估（惯性/情绪/环境摩擦大→优先环境方案而非意志力方案） | 每个关键断言带"这基于…"前提标注；输出预设差异清单 |
| ③整体归元 | 比对预设差异→回归认知起点（禁止和稀泥式折中） | 认知地图含维度/条件/权重 |
| ④留白开放 | 输出**留白声明**：①本结论依赖的未验证假设；②结论失效条件（什么变化需重估）；③迭代钩子（若补充Y信息可深化Z） | 至少1条未验证假设+1个迭代钩子 |

**循环控制器（六个）：**
1. **收敛判据**：主判据=连续两轮**无新增实质维度**（可数、可复现；判据原生出处= DS发散版 v3.1 的收敛表述，与"连续两轮无实质性不同新维度"同义，见头部①）。**实质维度操作定义**【TB1/TB2/TB3：无此定义则收敛时点靠裁量】：本轮出现了此前任何轮次都没有的、会改变认知地图组织方式的元素——新的关键变量/新的利益相关方/新的约束条件/新的结构性对立；对已有维度的重复表述、换措辞、深化细化均不计入。终止时标注收敛类型：**认知饱和型**（有输入而无新维度）或**输入枯竭型**（检索/信息耗尽——须在留白声明中写明，条件允许时优先补输入再判收）。跨域例外：连续两轮无新维度后突然出现新维度 → 标记"潜在跨域发现"，追加2轮验证。**提前收敛补漏**：深度档若在12轮前收敛，终停前做一轮覆盖性扫描（快速过一遍未涉及的结构类型与利益相关方）——依据实测"15轮覆盖性最优"。
2. **空转熔断**：连续3轮无实质进展 → 强制复位，执行**五步仪式**：强制暂停→接受此刻为新定位（只问"我现在在哪"）→盘点手中所有→重设最近的60分→重启。
3. **验证点成就锁**（60分成就锁，按验证点性质分流）：循环内验证点（分析结论/文件/测试可即时验证）→ 被外部检查点**证实**即快照+询问"继续冲理想状态还是停"；现实侧验证点（需用户线下动作）→ 不设锁，转为 Phase 4 验证任务，交付时声明"该验证点由现实信号判定"。锁的触发只有通过/未通过二元状态，无百分比（零节原则2/3）。**多验证点并行时按点独立判定**：任一关键验证点未过 = 整体未达成，交付时逐点说明过/未过及证据【TB1】。**对话式形态下，成就锁与停机判据同时满足时直接停机交付，不发"继续吗"询问**（停机优先）【TB4】。
4. **关键变量缺失停机**：识别出"某一回答可能改变结论"且该变量只有用户知道时，**暂停循环**提出该问题（一次只问一个），带答案继续。禁止带着缺口硬收敛，也禁止一次性抛出问题清单。与 0a 闸门分工：闸门管接入期缺口，本控制器管**循环中新暴露**的结论改变型缺口——问诊结束后循环中暴露的缺口必须走本控制器，不得依赖执行者自觉。
5. **归元式压缩**：每3-5轮做一次"抛开过程，当前核心矛盾是什么？距120/60各多远？"，结论写入定位卡，抛弃过程细节——防上下文超载诱发"妥协"病理。
6. **轮数封顶**：到档位上限无条件停机，交付已收敛部分+留白声明清单。

### Phase 3｜交付：输出层防火墙（对照实验中价值≈60%的最高价值组件）

内部淬炼过程（四阶、预设差异清单、留白声明、自检）**不进入交付物**。**交付物全文禁分**：不出现任何评分、百分比、进度数、概率值（零节原则2）；进展只以验证点状态与证据级别表达。

**交付七要素**：①核心结论（一句话大白话）②维度张力（2-3个）③适用边界（何时有效）④**退出条件**（出现什么信号即放弃/重开——静态适用域≠动态放弃规则）⑤具体交付物（方案/清单/表格/话术）⑥最低行动单元（低到不可能失败的第一步）⑦**一个留白声明**（当前最关键的未验证假设，用户能懂的语言）。

**交付模式**（按任务类型选一）：
- 模式1 快速归元（日常）：内部完整四阶，外部=结论+边界+行动单元+1条留白声明。
- 模式2 深度推演（战略规划类）：完整七要素。
- 模式3 逆向工程（诊断类）：呈现=从终局倒序、先给震撼再给方案，不暴露倒拆过程；内容底盘=**完整七要素**（模式3只定义呈现顺序，不减少要素）。选择判据：结论与用户自我认知冲突、任务本质是诊断→模式3；战略规划→模式2。
- 模式4 解释型交付（学习类）：五段结构=小白版→专业版→对应关系表→最易理解错处→3个理解自检问题（模板自带于本条）。模式4结构优先；退出条件并入随附验证任务的"停止信号"，最低行动单元并入"明天第一个动作"——两者属 Phase 4 验证任务，不并入解释本体。学习类轮次迭代对象依次为：理解深度→类比选择→讲解顺序→话术→演练。

**反幻觉红线（六条）**：
1. 一切数字/案例断言必须能指回外部锚；无锚数字不写。（锚点教训：一次对外演示材料曾混入无锚数字）
2. **事实/推断/观点三分书写**；对外材料中的数字必须是"已证实"级且**就近标注来源与日期**；来源未注明日期的，标注"来源未注明日期"并降一级处理。
3. **证据五级标注**：已证实 / 基本成立需收窄 / 存在争议 / 证据不足 / 明显错误。分级锚定：**"已证实"=官方一手来源（官方文档/论文/财报/多来源独立一致）；利益相关的二手来源（厂商博客/自媒体/渠道商内容）最高标"基本成立需收窄"并注明利益相关**。弱来源环境下五级实际按三级使用属正常，如实标注即可，不得为凑"已证实"放宽标准。**B 版一切不确定性表达统一走五级标注与留白声明，不使用概率化措辞（"较高可能性"等）**。
4. **冲突信息并列呈现**，不静默择一。
5. 结论质量靠**结构保障而非自评打分**：对立面是否充分看清单、覆盖是否足够看结构类型扫描、判断是否可靠看多角度交叉验证（多套理论多角度解释同一事件，结果相近则可信度升）。**不对自己的输出做分数化自评**。
6. AI 的均衡分析不得替代用户体感权重（框架锻造者红线）。

### Phase 4｜定位更新与现实验证外环

> 验证的裁判是现实，不是自我评估。

1. **60分达成判定优先绑定现实可观测信号**（实验指标/外部检查点），自我评估仅作辅助。
2. **验证任务**：交付时若结论包含可检验假设，追加一个**最小实验**——低成本、可逆、7天级（或用户可接受周期），格式：具体做什么/投入多少/观察什么指标/**什么结果支持继续/什么结果提醒停止**/实验结束获得什么新信息 + 明天就能开始的第一个动作。
3. **实验结果 = 下一次定位更新的外部锚**：下轮 Phase 1 盘点必须录入上个实验的观测结果。个人版 RLHF 飞轮的现实端：阅历→框架→AI执行→**现实暴露盲区**→迭代框架。
4. **沉淀**：区分"有效反复 vs 空转反复"；新跨域结构写入已验证结构库（现有5条：情感能量闭环/消费防火墙/演化力学/拓扑思维/两仪归元本体），标注适用条件与失效条件。

### 贯穿全程｜人机分工（框架锻造者范式，S级）

- **人（40%）**：提出/校准框架、注入阅历校准前提、体感验证真伪、元认知迭代、时机直觉
- **AI（60%）**：框架内穷尽拆解、逻辑推演、论据收集、快速测试、整合交付
- 执行口径："骨架主权+血肉外包"：框架主权在人→AI完善细节→AI反向解释帮人吸收→人基于判断修幻觉→结合自身经历迭代。

## 六、技术实现三形态（按落地成本排序）

### 形态A：单体系统提示词（最快，1-2天）
从3155行内核裁剪**控制逻辑精简版（≤500行）**。裁剪依据：对照实验（输出层防火墙≈60% > 四阶流水线≈30% > 角色包装≈10%）→ **保防火墙+四阶核心，删角色包装**；向量路径理论（S级双平台）"越好的模型提示词宜越简，复杂提示词会扭曲向量路径"→ 压成控制逻辑而非要求堆砌。
**B 版保留清单**：四阶（每阶一句过关标准）+ 预设差异清单 + 留白声明 + 防火墙七要素 + 伦理安全阀 + 模块触发表 + 六控制器。**B 版裁剪中不出现**：ΔP 数值、虚白坐标字样、概率化表述指令、球体图谱措辞。

### 形态B：Agent工作流（SKILL.md，3-7天）
归元论四模块翻成 skill 工作流（与常规 agent skill 同构）：
- 定位系统 → 状态盘（Phase 1 定位卡+每轮更新）
- 目标架构器 → Phase 0a/0b（闸门+120/60+形态判定+定档）
- 元认知引擎 → Phase 2 四阶循环 + 六控制器
- 欲望/动力管理 → 成就锁+熔断+封顶+验证任务
工程点：收敛用"新增实质维度计数"，可数可查，无需任何概率组件。

### 形态C：纯人工运行协议（零成本，即刻可用）
一页纸：澄清→定档→每轮一行四阶日志（对立面/新维度/控制器动作）→控制器触发即停→七要素写结论→定一个最小实验。消费防火墙首战即此形态实例。

## 九、A/B 测试指引（B 版随附；A 版未随本仓库发布，此节保留作方法论记录）

1. 同一个真实任务，分别用 A、B 各跑一遍（推荐形态C人工跑，成本最低；或两个子agent各加载一版）。
2. 对比五项：
   - A 的 ΔP 数值在两次独立运行间是否稳定复现（不复现=拍脑袋实锤）；
   - A 的虚白坐标是否产生了留白声明覆盖不到的洞察（没有=装饰性标签）；
   - B 的留白声明+五级标注是否同样覆盖了 A 标注的未知（覆盖=黑盒件冗余）；
   - 两版交付物的可用性差异（给你自己用体感判断）；
   - 执行负担（B 应显著更轻：少两组数字要编）。
3. 裁定规则：B 在前三项不输 → B 胜出，A 的待测组件删除或降为附录；A 的虚白坐标产生增量洞察 → 该组件单独回收入 B。
